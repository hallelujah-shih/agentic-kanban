# 派发方协议（内核）

把任务派给独立会话（子 agent / 客户端会话）执行，是派发方的责任。本文只写与客户端无关的协议内核；具体命令见 <skill_dir>/references/client-opencode.md。

`<skill_dir>` ＝本 skill 树的**绝对路径**（SKILL.md 所在目录）；派发稿里必须替换成实际路径。

## 何时派（动手前先过这道门）

判据用「变更面」事实，不用体量直觉。动手前一句话**归属声明**：「这轮派给 worker / 我自己做，判据是 X」——会话内可核对到这句，否决不靠事后追查、只靠这一句。

- **必派**（任一命中即派给 worker，主循环不写生产代码）：跨文件 / 新增模块 / 新增依赖 / 新增测试文件 / 真实外部系统写入（改生产数据、发真实邮件、写规则表等）。
- **可自做**（唯一自做通道）：仅「不改变行为且单一口径」的改动——文档 / 文案 / 常量，含同一事实的多处镜像同步。跨模块或改行为（客户/用户可见语义变化）一律派发。
- **开工前检查动作**（动作，不是自省）：祈使句进来先 `list_tasks` 查有无对应需求；没有就先用 `new_requirement` + `set_expectations` 建，再派。
- **配置分界**（「配置」一词下既有纯人读文档、也有改真实行为的系统配置，按执行面分，不按类别放行）：
  - 豁免清单（可自做，无需派发）：纯人读文档/环境卡、不入仓的一次性脚本、凭据与代理等环境面。
  - 反向清单（必须派发）：会被机器执行且改变真实行为的配置——systemd 单元、规则表、Gmail filter、MCP 使能配置（项目级 opencode.json 的 MCP 注册条目，决定 worker 能否上看板；可达性首跑偶有 flake，按预检复跑一次再判，不是一次不可达就拒）。
  - 留痕：凡触及行为面的配置变更（含豁免项里忽然发现改了真实行为），改完留一条记录（改了什么 + 为什么），不静默。
- 一个需求 = 一个 worker；同需求不并行 worker（认领排他会挡住第二个）。

## 预检（派发前逐项核）

1. **工作目录状态**：目标目录有未提交改动或有并发会话 -> 用隔离工作区（worktree）或等。
2. **工作区上下文**：环境卡或其等价来源（需求 description 指针 / README + 目录结构）。缺则自建最小上下文，并在派发稿注明「无环境卡，按 <来源> 自建」，不要因此停摆。
3. **目标目录能连上看板**：MCP 注册就位，DB 路径（环境变量）与派发方一致或明确指向临时 DB。用 `opencode mcp list` 核时，**首跑报「不可达」要复跑一次再判**——已实测（2026-10-30 Gmail 批）opencode.json 配置齐全时首跑仍偶报「No MCP servers configured」，复跑立即正常；按一次结果判不可达会误拒派。复跑仍不可达才按不可达处置，首跑 flake 的依据记进 note。目标目录刚创建（新 worktree / 新项目目录）-> **派发前先在该目录跑一次 `opencode mcp list` 作 warm-up**：warm-up 报空是已知首开 flake（2026-10-30 两例实测：新目录连空 2 次、第 3 次正常），不作不可达结论；派发入口预检仍复跑一次再判。派发入口（`agent-kanban dispatch`）把本项做成硬门：在目标目录跑 `opencode mcp list`（命令可经 env `AGENT_KANBAN_DISPATCH_MCP_LIST_CMD` 覆盖），首跑不可达复跑一次，复跑仍不可达即拒派（错误码 `mcp_unreachable`，不建会话、不写板 note）；workspace 指针缺失时跳过本项（worker 就绪门自核）。
4. **落点**：交付物类需求的会话工作目录指向**永久位置**（项目目录 / worktree），不指向批次临时目录——临时工作区里的产物在交接前必须搬到永久位置。

## 派发稿五要素

语义权威在本节；填空形状见 <skill_dir>/templates/dispatch-brief.md>。

1. **任务指针**：需求 id + 标题 + 指针行（不把需求全文塞进 prompt）。
2. **协议入口**：本 skill 树路径（`<skill_dir>/SKILL.md` 的实际路径）。
3. **上下文来源**：环境卡路径或其等价来源；同需求有历史时附历轮交付物。
4. **交付规格**：产物落点（从环境卡或等价来源抽取；缺则给跨项目归属指路）+ 验收锚 + 看板兜底指令（worker 拿不到 kanban MCP 工具（预检跳过或环境漂移）-> 立即停止并报告，写板面不可达走 CLI 正典路径；不硬写代码、不静默继续——派发稿必带，与落点提醒同位置）。
5. **红线提醒 + 墙钟预算**：禁项照抄；预算写清。

模板：<skill_dir>/templates/dispatch-brief.md。禁向 worker 承诺 release（release 是人面操作，agent 面不可达）：完成收尾＝worker 留 note 报完成 + 派发方人面代执行 release。

## 留痕（恢复锚）

派发入口自动经人面 note 留痕：首行写「分发 / 续跑 + 会话 id + 模型」，结局在正文。手工派发时自己 `add_record(kind=note)`：会话 id + 模型 + transcript 位置 + 预算——这条 note 就是恢复锚（见 SKILL.md「Session 与恢复」）。

## 验收

worker 的 `request_review` 是回执，不是完成。派发方按板面三问自答核交付：对照预期锚 / 偏离 / 有更好的方案吗。**不代 worker 交接**。

## 循环（返工）

人 REOPEN 后派新指令给同一会话（带上下文）：返工意见写明「哪里不达标 + 参照哪条锚」，不要只说「再改改」。同一需求续派时沿用同一会话，上下文不丢。

## 长段心跳

长任务需要有人替它续租（租约不因写操作延长）。客户端支持后台派发时，由后台进程按周期代续租，终态写一条 note（存活时长 / 续租次数），防活着的 worker 中途被判 STALE。

已知局限：后台进程随派发方终端退出即停（结构替代＝客户端侧插件心跳，本包不含）。派发方会话预计会死时，提前告诉人这条任务需要人工续租。

## 收尾蒸馏核验

worker 按 SKILL.md「交接与等待 -> 收尾蒸馏」自蒸馏（环境卡 + 板 note）；派发方只核验落点在板面可见，缺则补记，不重复定义义务。
