# 派发稿模板（五要素填空）

派发稿是给一个**没有你上下文**的新会话看的。五要素的语义权威见
<skill_dir>/references/dispatch.md「派发稿五要素」，本文件只给填空形状。照下面五段填，别把需求全文贴进去，也别让 worker 自由发挥。

```
需求：<需求 id>（<标题>）
先读：<skill_dir>/SKILL.md，按协议执行（认领 -> 接单确认 -> 拆解 -> 执行 -> 交接）
工作区：<绝对路径>（已就绪 / 需先建 <形状>）
上下文来源：<环境卡路径>（无环境卡时写：按 <需求 description / README + 目录结构> 自建最小上下文，推断写进接单确认的假设段）
交付规格：
  - 产物落点：<永久位置绝对路径>（禁落批次临时目录；临时产物交接前移到永久位置）
  - 验收锚：<需求 acceptance 逐条，或「需求 acceptance 为空 -> 你拆出的验收＝事实锚」>
  - 交付形态：<文件 / 分支 / PR / 报告>
历轮交付物：<同需求有历史时列 路径 + 一句话；无则写「无」>
红线：<禁直推主分支 / 生产只读 / 禁某目录 / 不动某模块>
预算：<墙钟预算>；<到点先交现有结论，不硬撑>
```

要点：

- **协议入口**写实际绝对路径（skill 树里 `SKILL.md` 的真实位置），不写相对路径。
- **红线条目**照抄，不要改写成「注意安全」这类不可判定的说法。
- 需要人裁决的事不要写进派发稿让 worker 自己决定——那是 `mark_blocked` 的触发面。
- 不要向 worker 承诺 release：完成收尾＝worker 留 note 报完成，派发方人面代执行 release。
