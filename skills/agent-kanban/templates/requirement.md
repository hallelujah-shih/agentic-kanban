# 需求登记模板（workspace 指针 + 验收锚）

需求登记（`new` / CLI 人面入口）是把「原始需求」变成「worker 能执行的东西」的那一步。写清三件事：从哪来、在哪做、做完怎么算完成。

```
标题：<一句话，动宾结构>
description：
  workspace=<工作区绝对路径> env-card=<环境卡路径或 none>
  <任务级例外：本次只读某目录 / 只改某模块 / 需要某环境>
  来源：<Jira / 文档 / 会话原话>（不抄全文，给可回溯的指针）
acceptance：
  1. <可判定的完成条件：谁能用什么方式验证>
  2. ...
```

要点：

- **workspace 指针** 一行写完，便于解析；不写「见环境卡」却不给路径。
- **acceptance** 写「可判定」的条件：能被命令、文件、链接或一段可核对的文本验证。别写「质量好」「尽量优化」。
- 验收为空是允许的：此时 worker 拆解出的子任务验收＝事实锚，交接时提请人确认/升格。空验收不等于随便做。
- 需求里缺失的约束（环境、权限、落点）留给 worker 在接单确认的「假设」段暴露，不要靠 worker 猜。
- 一条需求一个目标；要做两件事就开两条，避免验收锚互相污染。
