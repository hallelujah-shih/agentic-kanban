# ADR 0004 - Jira 范围裁决 + 单一事件源原则：不做自动导入，只做指针 + 摘要登记

状态: 已定（user 裁决）
日期: 2026-10-22
关联: PRD §0.1 / §4.2 / §8 / §11；design.md §7；ADR 0001（无候选满足合取）；ADR 0003（M0 决策，回写默认不做）

## 背景

PRD v3.2 原计划 M1 交付「Jira 导入」（`jira import <key>`：导入需求，原文入 description）。用户裁决：不做 Jira 自动导入——「只需要说明，给好链接即可，现在 ai 都能处理，不要做 ai 已经能做得很好的事情」。

## 决策

1. **不做 Jira 自动导入**：Jira 需求以链接引用登记——`new --source jira --source-ref <链接>`，`description` 贴摘要，完整详情留在 Jira（单一事件源）由 agent 自行获取（AI 读取链接是已能做好的能力，导入属重复造轮子）。
2. **回写维持不做**（PRD §11 默认 + ADR 0003 语境），一并钉死为「不做」。
3. 实现面：service（new_requirement 的 source/source_ref）与 REST（POST /requirements）原本已支持；CLI `new` 补 `--source/--source-ref` 参数，使链接登记在三个面（CLI/REST）一致可用。
4. **单一事件源原则（推广，user 裁决「其他也要参考这个决定」）**：看板只登记指针 + 摘要，完整内容留在源头；适用于一切外部有单一事件源的内容（Jira 详情、代码/PR、会话原文）。登记是 URL+摘要 还是完整详情不重要，做好指引更重要——需要完整内容时由 agent 从源头获取。与反淹没互补：反淹没 = 不默认展示，本原则 = 不留存、只指引。

## 理由

- 导入的价值 = 免人工抄写；但完整详情本身也不应入看板——单一事件源要求内容留在源头，看板做好指引（URL + 摘要）即可，agent 自行获取完整内容。
- 全局不做清单原则（AI 已能做好的事不重复造）适用于导入；回写同理（默认不做维持）。
- 不影响状态机/租约/视图等核心契约；仅收窄 M1 范围。

## 影响

- PRD：§0 定位新增「单一事件源（指引优先）」原则、§0.1 不做清单、§4.2 人面命令、§8 M1 行、§11 未决表、§7.2 cli.py 注释同步；requirements.description 语义 = 摘要（非原文）。
- design.md：§1/§7/M1 行同步；requirements 表 description(摘要)。
- M1 交付收窄为「Web 窗口」+ AC14；G3 基线采集仍为 M1 硬前置。
- 无既有代码删除（jira import 从未实现，仅规格存在）；CLI `new` 新增 `--source/--source-ref` 参数（service/REST 原本已支持）。
