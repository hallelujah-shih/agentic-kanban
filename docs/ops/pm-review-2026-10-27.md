## 1. 定位（strategy-session Phase 1）

定位声明（强制填空）：「为驱动 AI agent 干真实活的 solo 开发者，需要不费劲回答每
个需求的三问、且终态只有人确认才可信、决策可回溯；AgenticKanban 是带人确认闭环的
看板记录面，提供关键节点暴露 + 决策审计；不同于 agent 自报/会话考古，终态人确认
才可信、actor 服务端派生不可伪造。」

- 定位成立：核心承诺对应 user 亲历的痛（g3-trial/baseline-week-log.md 示例条目：
  agent 说「差不多了」实际 2/3 规则未回放，半天排查 + 一次线上抖动）。
- 「看板」是方案锚不是问题锚：真问题＝agent 工作黑箱 + 终态不可信 + 关键节点不可读；
  outcome 已由 PRD §1 C1 三问定义。
- 无市场信号：唯一客户是 builder。单用户工具合法，但每批须问「这是不是我能消掉的
  最高价值摩擦」——最近两批未证明。

## 2. 问题框定画布（MITRE）

Look Inward：solution-first（立项即叫「看板」）；builder bias（每批需求源＝builder
当下手感，须对三问 outcome 交叉检验）；自指循环（看板记录看板自己的开发，复盘产出
下批改进清单——循环真实但 objective function 是「建设过程更顺」非「三问更可答」）。

Look Outward：问题人群＝驱动多 agent 的 solo 开发者（存在但无市场通道）；无此问题者
＝单 agent/容忍自报/无审计要求用户；被排除者＝其他人类（信任模型 C 结构性单用户，
不为第二用户建）；受益于问题存在者＝诚实答案是项目本身（问题在则批次不断），唯一
对冲＝G3 验证实验——而它没在跑。

Reframe：问题是 solo agent 运营者无法不费劲回答三问（关键节点在会话黑箱、终态 agent
自报），根因不是缺看板而是缺「人确认才可信的终态 + 不展开就能答三问的摘要面」。
HMW：如何让每个需求的三问从摘要视图不费劲答得出、每个 DONE 可回溯到一次人的决定，
使确认 <1 分钟、回溯无需会话考古。
