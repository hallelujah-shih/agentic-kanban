# G3 试用协议（AC14 硬前置 + 痛点基线采集）

关联：PRD §1 C1（三问）/ §8 M1 行 / §9 AC14 / §10 G3；known-gaps G3。
产物：本文件（协议）+ `baseline-week-log.md`（第 0 周填写）+ `trial-week-scorecard.md`（第 1 周填写）。
基线数据回来后定：反淹没主观评分阈值 + AC14 通过判定 + M1 完成判定。

## 目标与判定（PRD AC14 逐字）

一周试用协议：真实需求 N >= 5；每个需求逐项回答三问并打分；"无法回答"计数为 0 且反淹没主观评分 >= 阈值（阈值第 0 周末按基线定）；G3 基线采集完成是前置条件。

三问（C1，对照预期验收 / 是否偏离 / 是否有更好方案）：
1. 符合预期吗？—— 当前进展对照需求登记的预期验收锚（含验收项覆盖缺口），是否在预期轨道上。
2. 有偏离吗？—— 结构性偏离（blocked/abandoned/重试超限/里程碑延误等派生信号），是否有人需要决策的偏离。
3. 有更好方案吗？—— 事件流中的决策/备选/风险，是否存在当前路径之外的更优选项。

## 两周结构

### 第 0 周：基线周（不用看板）

- 用你平时的方式（不开 agent-kanban）驱动 AI agent 做真实工作，>= 3 个任务。
- 每个任务在 `baseline-week-log.md` 记一条（当日记，禁止周末补记——记忆衰减使数据失效）。
- 重点采集：你想了解 agent 状态时，实际发生了什么（问人/翻日志/凭感觉/没发现）。
- 周末：分析基线日志，定反淹没主观评分阈值（判分表见下），写进 `trial-week-scorecard.md` 头部。

### 第 1 周：试用周（用看板）

- N >= 5 个真实需求走看板全流程：登记（new + set_expectations，带来源指针+摘要+验收锚）-> agent 认领/拆解/执行/交接 -> 人裁决（approve/reject/reopen）。
- 每个需求在 `trial-week-scorecard.md` 逐项回答三问并打分。
- **三问纪律**：只允许用摘要视图作答（Web 看板/深潜页，或 CLI `view` 的 summary 输出）——不展开事件流、不读原始输出、不额外问 agent。答不出就如实记"无法回答"+ 卡在哪。
- 当日记，禁止攒到周末。

## 反淹没主观评分表（1-5）

对每个需求回答三问后，评"摘要视图是否让你不费劲地拿到了三问所需的关键节点"：

| 分 | 定义 |
|---|---|
| 5 | 一眼看到三问材料，零无关信息 |
| 4 | 关键节点清晰，无噪声感 |
| 3 | 关键节点基本清晰，有轻微噪声 |
| 2 | 能拿到但噪声明显，需要费力过滤 |
| 1 | 信息淹没，必须展开事件流/额外问 agent 才能答 |

阈值在第 0 周末定：参照基线周你"靠现有方式答三问"的体验对位（例：基线体验相当于 2 分，则试用阈值定 3 分；相当于 1 分，则阈值可定 3-4 分——取"明确优于现状"的最低分）。阈值定多少、为什么，写进 scorecard 头部留档。

## 周中检查点（第 3 天自查，各 1 分钟）

第 0 周：
- 日志已有 >= 2 天条目。
- 每条都有"三问映射"列（没有映射的条目对定阈值无用）。

第 1 周：
- 已登记需求 >= 3 个且至少 1 个在 CLAIMED 之后（节奏够到 N>=5）。
- scorecard 当日在记（不是攒的）。
- 至少 1 个需求走过 request_review（没走到 = 下周 AC14 的"交接->裁决"面缺数据）。
- 卡住的问题已记入 scorecard"卡点"栏（卡点是数据，不是失败；看板答不出的题正是 AC14 要暴露的）。

## 工具速查

```
# 启动服务（REST + Web 窗口 + MCP HTTP，默认 127.0.0.1:8765）
uv run python -m agent_kanban.api
# 环境变量：AGENT_KANBAN_PORT / AGENT_KANBAN_HOST / AGENT_KANBAN_TOKEN / AGENT_KANBAN_DB
# DB 默认 ~/.agent-kanban/kanban.db

# Web 窗口（人看）
http://127.0.0.1:8765/            # 看板（全部非终态需求 + 派生信号徽标 + 风险）
http://127.0.0.1:8765/requirements/<id>  # 深潜（里程碑/决策/风险/偏离/需要关注/事件流）

# MCP（agent 面，二选一）
agent-kanban mcp                   # stdio（每进程独立连接）
http://127.0.0.1:8765/mcp          # streamable-http

# CLI（人面）
agent-kanban new --title ... --description ...   # 登记需求（来源指针+摘要）
agent-kanban set_expectations --requirement-id ... # 设预期验收锚
agent-kanban view --requirement-id ...           # 摘要/详情
agent-kanban approve / release / note / abandon / reopen / renew
agent-kanban export                # 全量导出（回溯/归档）
```

agent 侧协议：`skills/agent-kanban/SKILL.md`（放进你 agent 的 skill 目录；门序、记录纪律、报告纪律都在里面）。

## 结束判定（第 1 周末）

1. N >= 5 且每个需求三问逐项有答（"无法回答"计数 = 0）。
2. 反淹没主观评分（N 个需求均值）>= 第 0 周定的阈值。
3. 第 0 周基线日志完整（G3 闭合）。
-> 全部满足 = AC14 通过、G3 闭合、M1 完成判定成立。不满足项逐条记录（是看板缺口 = M2 输入，还是用法问题 = 修用法）。
