# 基线周日志（第 0 周，不用看板）

任务：用平时的方式驱动 AI agent 做真实工作（>= 3 个任务），每个任务当日记一条。禁止周末补记。

## 填写模板（每个任务一条，复制往下填）

```
### [日期] [任务一句话]
- 当时状态怎么知道的：（问 agent / 翻日志 / 看产物 / 凭感觉 / 没主动了解）
- 痛点：（想了解什么但没拿到 / 发现了什么不对劲 / 什么都没发现）
- 怎么发现的：（谁告诉你 / 自己撞见 / 至今没发现）
- 代价：（花了多久 / 打断了什么 / 延迟多久才知）
- 三问映射：（这条痛点属于 1 符合预期 / 2 有偏离 / 3 更好方案 哪一问；当时答得出吗 是/否/部分；怎么答的）
- （可选）若当时有看板，哪个视图本应显示：
```

## 示例（粒度参照，勿抄）

```
### 2026-10-24 [waf 规则热更脚本改造]
- 当时状态怎么知道的：问 agent "做到哪了"，它说"差不多了"
- 痛点：不知道"差不多"是指验收项过了还是代码写完了；它说改完的 3 条规则，实际只回放了 2 条
- 怎么发现的：第二天线上告警，回放时自己跑的
- 代价：半天排查 + 一次线上抖动
- 三问映射：1 符合预期——答不出。没有任何对照锚，"差不多"无法验证
- （可选）若当时有看板：摘要视图的验收项覆盖对照 + request_review 证据本应拦住
```

## 周末产出

1. 统计：N 条日志中，三问映射的分布（1/2/3 各几条）、"当时答得出"的占比。
2. 定阈值：把基线体验对位到 1-5 分表（见 protocol.md），写反淹没主观评分阈值到 `trial-week-scorecard.md` 头部，附一句理由。
3. 本文件 + scorecard 头部提交（git），作为 AC14 判定基线留档。
